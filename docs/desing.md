# 家庭券夹 · 需求与实现方案

供家中老人现场出示券码的轻量应用，采用 Python 单文件后端、本地 JSON、单个 HTML 模板和 Docker Compose。移动端满屏、浅色、简约，优先适配 iPhone 和老人操作习惯。

本文是实现与验收依据；应用代码和部署文件位于项目根目录，启动说明见根目录 README.md。

## 1. 目标与架构

给家中老人现场展示券号和券密，长按三秒记录使用。家人在电脑上管理券池。主要供一个家庭使用，所有设备共享服务器上的同一份使用记录。

- 一个 `app.py`：Flask 后端，负责登录校验、页面、券码接口和 JSON 读写。
- 一个 `templates/index.html`：包含 HTML、CSS 和少量原生 JavaScript，同时呈现老人界面和管理界面。
- 一个 `data/data.json`：保存密码哈希、券码及操作记录。
- Docker Compose：启动一个应用容器，将数据目录挂载到服务器本地。
- 不用 Gist、GitHub Token、Node.js、前端框架、打包构建或数据库。
- localStorage 不保存券码、使用进度或解锁状态；服务器记录为唯一依据。

计划目录：

```text
family-coupons/
├── app.py
├── templates/
│   └── index.html
├── data/                 # 首次启动生成；不提交版本库
│   └── data.json
├── requirements.txt
├── Dockerfile
├── compose.yaml
├── .env.example
├── docs/desing.md
└── README.md
```

## 2. 页面与入口

统一入口 `/`，只有一个模板。初始 HTML 不包含券号、券密或密码哈希；验证通过后由接口返回需要展示的数据。

电脑宽屏显示一个不抢眼的“管理”入口。手机窄屏默认隐藏该入口，只显示老人流程。家人需要在手机上管理时，可直接访问 `/?view=admin`，仍复用同一模板。

屏幕宽度仅决定入口显示，不决定权限；任何设备进入管理功能都必须通过服务端管理员验证。

### 老人端

**密码页**：标题“请输入密码”，数字密码输入框，大按钮“查看券码”。不自动填充、不记住输入。提交中禁用重复操作。错误时清空输入，显示“密码不正确，请重试”。

**券码页**只显示：

```text
剩余 3 张（含本张）

卡号
0012 3456 7890

密码
001234

[ 按住3秒，标记已使用 ]
```

字号大、对比度高，长内容换行不截断，保留前导零。底层卡号保留原始字符串，分组只用于显示。不提供切换、复制、历史等按钮，不自动展示下一张。

**用完页**显示“券已用完 / 请联系家人添加”和“重新检查”。发现新增券后回到密码页，重新验证才展示。

每次启动、刷新、切后台再返回，以及使用完一张券，都需要重新输入进入密码。切后台立即从 DOM 移除敏感内容，取消长按，并作废本页内存中的解锁凭据。后台请求返回也不能重新显示券码。

### 电脑管理界面

管理员登录后提供：

| 功能 | 行为 |
| --- | --- |
| 库存概览 | 总数、未使用数、已使用数 |
| 单张添加 | 输入卡号和券密，保存前校验 |
| 批量添加 | 每行“卡号 密码”，空格或制表符分隔，忽略空行 |
| 批量预览 | 显示有效行、错误行和重复卡号；有错误时禁止整批导入 |
| 未使用列表 | 按添加顺序显示，允许修改券号及券密 |
| 已使用列表 | 按使用时间倒序，查看完整券号、券密和历史 |
| 恢复误标 | 确认后恢复未使用，保留此前使用及恢复事件 |
| 密码设置 | 修改老人进入密码、管理员密码 |
| 退出管理 | 清除管理会话及页面敏感内容 |

券号在整个券池内唯一，已使用券也参与查重。不提供永久删除，不增加分类、有效期、多人分配等功能。

## 3. 移动端视觉与适老化规范

### 满屏与自适应

- 页面铺满手机可用视口，不做带外框的手机模型，不在手机上显示居中的小卡片网站。背景延伸到整个屏幕，内容使用必要的内边距。
- 按 CSS 视口自适应，不按 iPhone 物理像素写死宽高。至少覆盖 320、375、390、393、414、430、440 CSS 像素宽度，也兼容更宽或更窄的设备。
- 使用 `width=device-width, initial-scale=1, viewport-fit=cover`；保留用户缩放能力，不设置禁止缩放。
- 页面采用 `min-height: 100dvh`，提供 `100vh` 回退。用最小高度而非固定高度，避免小屏或放大字体后截断内容。
- 顶部和底部适配 `safe-area-inset-*`，标题、券号和按钮避开刘海、灵动岛与底部 Home 指示条；横屏也保留左右安全区域。
- 普通内容、默认字号、键盘收起时，主要信息及按钮尽量一屏展示。长券号、大字体、横屏或软键盘展开时允许纵向滚动，不为强行一屏而缩小文字。
- 不出现横向滚动。按钮随页面正常布局，不用悬浮定位遮挡券码、提示或输入框。软键盘弹出后，密码输入框和提交按钮应可见或可滚动到达。

“满屏”指页面占满可用区域；Safari 打开时仍可能显示浏览器工具栏。从主屏幕启动的独立 Web App 是主要使用方式，不要求用户触发浏览器 Fullscreen API。

### 浅色与字体

固定浅色风格，不随系统深色模式自动变暗。使用系统字体，无需加载第三方字体、图片背景或组件库。

| 项目 | 设计要求 |
| --- | --- |
| 页面背景 | 暖白或浅灰白，例如 `#F7F8F5` |
| 主文字 | 接近黑色的深色，例如 `#182820` |
| 主按钮 | 深绿色，例如 `#245C48`，配白色文字 |
| 次要文字 | 清晰的深灰，例如 `#526158`，不使用浅灰小字承载重要提示 |
| 错误提示 | 深红色文字并写清原因，不只靠颜色区分 |
| 页面标题 | 约 30–36px，加粗 |
| 卡号、券密 | 约 36–48px，使用等宽数字，允许自适应换行 |
| 标签、剩余数量、提示 | 约 20–24px，行高约 1.5 |
| 按钮文字 | 约 22–26px，直接说明动作 |

正文与背景对比度目标至少 4.5:1。避免渐变、大面积装饰、复杂阴影、轮播和无关动画；长按进度是主要动态反馈。

### 三个页面的布局

**密码页**：上部显示“请输入密码”，中部放宽大的密码输入框和“查看券码”按钮，下方预留状态提示空间。页面不放营销文案、导航栏或无关图标。不自动聚焦强行弹出键盘，老人点击输入框后唤起数字键盘。

**券码页**：顶部显示剩余数量；中部以两组清晰标签和大字展示卡号、密码；主按钮放在下部易触达区域。券码是视觉重点，长按按钮与券密之间保持足够间距。正常状态只保留既定四项内容，出错或保存时才出现必要提示。

**用完页**：中部显示“券已用完”和“请联系家人添加”，下方放一个“重新检查”大按钮，不展示历史券码。

### 触摸与可读性

- 主按钮占满内容宽度，高度至少 72px，圆角约 16px；输入框高度至少 64px，输入文字至少 24px。
- 内容左右留白约 20–24px，小屏可以适当收窄；独立操作区域之间至少留 16px 间距。
- 按钮有明显按下、禁用、保存中状态；不要只显示转圈，必须配“正在记录…”等文字。
- 长按期间显示填充进度和剩余秒数，松开或移出立即复位。仅在长按按钮区域禁用文字选择、系统长按菜单和干扰手势，不全局禁止缩放或滚动。
- 券号及券密不省略、不截断，不用极小字号塞进一行；卡号分组只用于显示，不改变原数据。
- 输入框有明确标签，提示可由读屏软件播报。放大文字后仍可完成整个流程，不依赖悬停或精细点击。

电脑端沿用浅色视觉，管理区域可以使用受限宽度和多列排版。手机老人端不套用电脑的侧栏、表格或多列布局。

## 4. 密码与权限

改为服务端验证，采用两个密码：

- **老人进入密码**：纯数字，只能查看当前券及标记这张券。
- **管理员密码**：家人设置，用于添加、修改、恢复及密码管理。

两者分别保存为带盐密码哈希，不保存明文。这个小幅调整可以避免仅凭老人密码操作整个券池。修改密码时，使对应的现有授权失效。

老人每次验证成功，获得一个短时、仅绑定当前券 ID 的随机凭据，保存在页面内存中。凭据过期、页面刷新或返回前台后，重新输入密码。成功标记后该凭据只能核实原操作结果，不能查看下一张。

管理员使用服务端会话和 HttpOnly Cookie；会话有空闲超时，写接口校验 CSRF。登录失败做基本限速。服务器日志不记录密码、券密或会话凭据。

首版固定单进程运行，授权状态保存在进程内存；容器重启后需要重新登录，不影响券码和使用记录。

## 5. 长按与保存

1. 按下按钮开始显示填充进度和倒计时，按实际经过时间判断三秒。
2. 未满三秒松手、手指移出按钮、触摸取消或页面隐藏，全部取消，进度归零。
3. 满三秒自动提交，不弹确认框；按钮显示“正在记录…”，禁止重复操作。
4. 后端验证本次授权、屏幕上那张券的 ID 及当前状态，再记录使用。
5. 写入成功后隐藏券码、清除授权，回到密码页并提示“上一张已记录使用，请输入密码查看下一张”。最后一张成功后进入用完页。
6. 明确保存失败时保留当前券和重试机会，不能提示成功。

每次标记生成一个操作 UUID。服务端把操作 ID 与使用事件一起保存；相同请求重试不会重复记账。

如果请求超时或连接断开，不推断成功或失败：隐藏券码并显示“正在确认使用结果，请勿重复验券”，提供“重新检查”。通过操作 ID 核实，必要时以同一个操作 ID 重试。待核实的操作 ID 可存 sessionStorage，刷新后仍先核实，里面不放券码或密码。会话失效时先重新验证进入密码，再核实原操作，不直接解锁下一张。

若当前券已由其他设备使用，隐藏当前券，回到密码页提示重新验证；不能把请求自动应用到下一张券。

## 6. 券码选择与数据

按 JSON 中添加顺序选择第一张 `unused` 券，不存当前下标。恢复误标时保留原位置，因此重新进入原顺序。

数据结构示意：

```json
{
  "schemaVersion": 1,
  "settings": {
    "accessPasswordHash": "带盐密码哈希",
    "adminPasswordHash": "带盐密码哈希"
  },
  "coupons": [
    {
      "id": "券UUID",
      "number": "001234567890",
      "password": "001234",
      "status": "unused",
      "createdAt": "2026-09-23T08:00:00Z",
      "usedAt": null
    }
  ],
  "events": [],
  "updatedAt": "2026-09-23T08:00:00Z"
}
```

事件保存 `id`、`type`、`couponId`（适用时）、`at`。记录添加、批量添加、使用、恢复、修改和密码变更；事件不保存旧密码或密码哈希。时间用 UTC 保存，界面按设备本地时间显示。

卡号、券密始终为字符串。老人密码在校验哈希前也按字符串处理，保留前导零。

## 7. 本地 JSON 的可靠写入

所有修改走同一个入口：

```text
获取写锁 → 读取并校验 JSON → 校验权限及目标状态
→ 应用本次变更 → 写临时文件并刷盘 → 原子替换 → 返回成功
```

- 部署一个容器、一个 Web 工作进程，进程内锁覆盖整个读改写过程，避免多个请求互相覆盖。
- 临时文件与目标文件位于同一挂载目录。写失败保留原文件，不误报成功。
- 已有文件格式异常时停止读写并报错，不重建空券池覆盖原数据。
- 只有首次部署且数据文件不存在时才初始化；已有数据不受启动环境变量覆盖。
- 不在运行中手动编辑 JSON。如需人工修复，先停容器并备份。
- 数据目录由服务器定期备份；不做管理界面里的备份系统。原子替换不等于备份。

单进程锁能够串行化写入，但无法防止两台手机同时在现场出示同一张尚未记录使用的券。首版仍以一台老人手机为主要使用设备，不增加预约占用功能。

## 8. Docker Compose 部署

- Flask 作为应用框架，由生产 WSGI 服务以一个工作进程运行，不用 Flask 开发服务器部署。
- `./data` 挂载到容器 `/app/data`，容器重建不丢数据。
- `.env` 提供首次初始化的老人密码和管理员密码；初始化后从 JSON 读取哈希，初始明文密码可从环境配置中移除。
- 容器配置自动重启和健康检查；健康检查只返回运行状态，不泄露券码。
- 默认端口绑定服务器回环地址，由现有反向代理提供 HTTPS。通过手机访问代理域名。
- `docker compose up -d --build` 完成构建启动。

初始化凭据缺失、文件损坏或目录不可写时，启动失败并给出明确的服务器日志，不使用默认密码或空数据兜底。

## 9. iPhone 桌面使用

模板包含 Apple Web App 元数据和安全区域样式。图标与 Manifest 可以由 `app.py` 的固定路由提供，无需增加第二个模板。不添加 Service Worker，不支持离线展示或离线排队写入。

用 Safari 打开 HTTPS 地址后添加到主屏幕。真机检查桌面启动、后台返回、长按菜单、触摸中断以及长内容换行。

## 10. 实现验收范围

- 错误密码不返回券码；仅凭老人授权不能调用管理接口。
- 启动、刷新、后台返回均重新要求密码，后台旧请求不能恢复敏感内容。
- 未使用时始终展示同一张，保留券号及券密前导零。
- 点击、短按、移出、触摸中断都不标记；长按三秒仅记录一次。
- 保存后不泄露下一张；最后一张进入用完页。
- 超时、断网、重复请求、写入失败均不会误报成功或重复记账。
- 添加、批量整体导入、已用券查重、修改和恢复正常。
- 并发修改不会丢失彼此的更新；损坏 JSON 不会被覆盖。
- Compose 重建及服务器重启后数据仍保留。
- 电脑显示管理入口，手机默认只显示老人流程。
- iPhone 不同宽度下背景满屏，无横向滚动，安全区域不遮挡内容。
- 普通长度券码在竖屏、默认字号和键盘收起时，券号、券密及操作按钮可一屏查看。
- 长券号、横屏、系统放大文字及软键盘展开时，内容完整且按钮可到达。
- 系统处于深色模式时，应用仍保持约定的浅色风格和清晰对比度。
- 真机主屏幕模式下长按不弹菜单，移出及切后台取消操作，返回后不残留券码。

实现时只围绕这些行为做必要测试，不重新引入前端工程化工具链。
